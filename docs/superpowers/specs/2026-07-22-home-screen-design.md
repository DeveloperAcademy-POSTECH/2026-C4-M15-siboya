# Home Screen Design

## 목적

검증된 Home 컴포넌트를 실제 번들 데이터와 연결해 태명, 주차별 추천, 카테고리별 대본 목록과 고정 하단 탭 바를 표시한다. 추천 카드와 대본 행은 동일한 이미지 시리즈를 용도에 맞는 크기의 에셋으로 해석하며, 데이터나 이미지 일부가 없어도 의존하지 않는 화면 영역은 계속 표시한다.

## 기준 자료와 우선순위

1. 레이아웃, 간격, 글자 역할과 230pt 추천 카드 구조는 Figma Home `1009:12231`을 따른다.
2. 태명과 현재 주차는 `BabyProfile`, 주차별 추천 문구와 추천 ID는 `home-weekly-content.json`, 대본·카테고리·주차는 `taedam-scripts.json`을 따른다.
3. Figma 샘플과 번들 콘텐츠가 다르면 번들 콘텐츠를 표시한다.
4. 이미지 파일은 사용자가 등록한 `TitleImage1...7` 및 `TitleImage1...7Card`를 사용한다.

## 이미지 시리즈 매핑

이미지 번호는 1부터 7까지인 `HomeArtworkSeries` 값으로 표현한다. 한 시리즈는 표시 위치에 따라 다음 이름을 계산한다.

| 표시 위치 | 계산 결과 예시 |
|---|---|
| 추천 카드 | `TitleImage1Card` |
| 대본 행 | `TitleImage1` |

- 추천 이미지는 20~40주 `weeks` 배열의 최초 등장 순서에 따라 1, 2, ..., 7을 배정하고 8번째에서 다시 1로 순환한다. 따라서 21개 주차 제목은 7개 시리즈를 정확히 세 번 사용한다.
- 행 이미지는 `scripts` 배열의 최초 등장 순서에 따라 같은 방식으로 순환한다. 현재 여섯 대본은 1~6번을 각각 사용한다.
- 순환은 배열 위치에 대한 결정적 규칙이므로 같은 번들 데이터는 실행할 때마다 같은 이미지를 사용한다.
- 추천 카드는 주차 제목의 순서, 행은 대본 순서에 각각 대응한다. 추천 대본이 목록에도 존재하더라도 두 위치의 이미지 번호가 같을 필요는 없다.
- 이미지 조회 실패는 데이터 실패가 아니다. 기존 `HomeArtworkView`가 같은 크기의 중립색 박스를 표시한다.

## 화면 상태와 데이터 변환

`HomeViewState`는 순수 표시 값만 보관한다.

```text
HomeViewState
├── babyNickname: String?
├── recommendation: HomeRecommendationState?
│   ├── headline: String
│   └── item: HomeScriptItem
└── categories: [HomeScriptCategory]
    ├── title: String
    └── items: [HomeScriptItem]
```

`HomeViewStateBuilder`는 프로필 스냅샷, Home 주차 문서와 대본 문서를 입력받아 다음 정책으로 상태를 만든다.

- 프로필이 있으면 trim한 태명을 Large Title에 사용한다.
- 프로필 주차와 정확히 같은 Home 항목 및 추천 ID와 정확히 같은 대본이 모두 있을 때만 추천 상태를 만든다.
- 추천 연결이 실패해도 카테고리 목록은 유지한다.
- 카테고리와 내부 대본 순서는 대본 JSON의 최초 등장 순서를 유지한다.
- 빈 카테고리나 빈 제목의 대본은 해당 항목만 제외한다.
- 추천 대본도 카테고리 목록에서 제외하지 않는다.

`HomeScreenModel`은 `TaedamRepository`, 두 번들 로더를 호출해 상태를 갱신하는 메인 액터 객체다. 각 데이터 소스의 실패를 독립적으로 허용해 정상 데이터가 있는 영역은 계속 만든다. `HomeView`는 로더, 저장소와 `ModelContext`를 알지 못하고 전달된 상태와 선택 콜백만 소비한다.

최신 `origin/develop`에 병합된 SCRUM-28 계약에 따라 온보딩이 없는 MVP에서는 앱 조립 지점이 `ensureBabyProfile(nickname:gestationalWeek:)`을 먼저 호출한다. 이 호출은 프로필이 없을 때만 기본값 `꾹꾹이`, `22주`를 한 번 저장하고, 기존 프로필이 있으면 수정하지 않는다. 그 다음 `HomeScreenModel`이 `fetchBabyProfile()`로 저장된 값을 다시 읽어 Home 상태를 만든다.

## 화면 조립

- `ContentView`는 앱 조립 지점으로서 환경의 `ModelContext`로 저장소를 만들고, MVP 기본 프로필의 멱등적 생성을 마친 뒤 `HomeScreenModel`의 로드를 시작한다.
- `HomeView`는 하나의 세로 `ScrollView` 안에 태명, 추천 영역, 카테고리 섹션을 순서대로 배치한다.
- 화면 배경은 adaptive system background를 사용해 라이트 모드의 밝은 Figma 인상과 다크 모드의 텍스트 대비를 함께 유지한다.
- 추천 영역은 `이번주 추천`, 주차별 headline, 230pt `HomeRecommendationCard`로 구성한다.
- 카테고리는 기존 `HomeCategorySection`을 사용한다.
- `HomeBottomTabBar`는 safe-area inset으로 화면 하단에 유지한다. 태담은 선택 상태이고 약속 버튼은 상위 콜백만 호출한다. 탭 제목은 semantic font를 사용하고 48pt를 최소 높이로 삼아 접근성 글자 크기에서 확장한다.
- 탭바 배경은 Figma의 95pt 하단 영역처럼 상단 절반까지 콘텐츠가 비치는 투명 상태에서 시작해 하단의 adaptive system background로 이어지는 단일 세로 gradient를 사용한다. 투명 gradient 뒤에 불투명 배경을 다시 두지 않으며, 하단 safe area까지 같은 fade를 확장한다.
- 추천 카드와 행 선택은 기존 계약대로 `(scriptID, scriptVersion)`을 상위 콜백에 전달한다. 현재 범위에서는 아직 없는 미리보기 화면을 직접 생성하지 않는다.

## 오류·빈 상태

- 프로필 누락: 태명과 추천 영역만 숨기고 대본 목록과 탭 바는 표시한다.
- Home 주차 문서 또는 현재 주차 항목 누락: 추천 영역만 숨긴다.
- 대본 문서 누락: 대본에 의존하는 추천 카드와 카테고리 목록을 숨긴다.
- 특정 추천 ID 연결 실패: 추천 영역만 숨긴다.
- 이미지 누락: 해당 이미지 영역만 박스로 대체한다.
- 표시 데이터가 전부 없어도 배경과 하단 탭 바는 유지한다.

## 접근성과 주석

- semantic font를 사용하고 긴 텍스트를 한 줄로 강제하지 않는다.
- 카드와 행은 각각 하나의 접근성 버튼이며 기존 label/value 계약을 유지한다.
- 하단 탭은 아이콘과 텍스트를 묶은 접근성 버튼으로 제공한다.
- 새로 추가하거나 수정하는 Swift 타입, 상태, 함수와 핵심 레이아웃에는 역할과 이유를 설명하는 한국어 주석을 작성한다.

## 검증 조건

- 이미지 시리즈 1과 7의 카드·행 에셋명이 정확하다.
- 8번째 순서가 1번으로 돌아온다.
- 21개 주차가 1~7을 세 번 반복한다.
- 여섯 대본의 행 이미지가 JSON 순서에 따라 결정된다.
- 추천 연결 실패, 프로필 누락과 빈 대본이 다른 정상 영역을 제거하지 않는다.
- 추천 카드 높이는 계속 230pt다.
- 다크 모드의 화면 배경이 어둡게 렌더링되고, 접근성 글자 크기에서 하단 탭 높이가 확장된다.
- 하단 탭바의 상단은 뒤 콘텐츠가 비치고 하단은 system background로 페이드되어 흰색 단색 띠로 보이지 않는다.
- 집중 테스트, 전체 테스트와 iOS Simulator 빌드가 통과한다.
