# 태담 진행·녹음 및 버킷리스트 저장 백로그

- **상태**: draft
- **최종 수정일**: 2026-07-15
- **담당 영역**: 태담 시작, 대본 진행, 버킷리스트 발화 전사, 녹음 제어, 음성 분석 및 저장
- **관련 Feature**: `Siboya/Features/Taedam`
- **관련 Core**: `Siboya/Core/Services/Audio`, `Siboya/Core/Services/Analysis`
- **관련 Persistence**: `Siboya/Persistence`

## 사용자 스토리

직장인 예비 아빠로서 태담을 시작할 때 제공된 대본을 자연스럽게 따라 읽고, 마지막에는 아기와 함께하고 싶은 버킷리스트를 직접 이야기해 녹음과 버킷리스트 기록으로 남기고 싶다.

## 출시 결과

이 백로그가 완료되면 사용자는 태담 화면에서 시작 버튼을 눌러 준비된 대본을 따라 읽고, 마지막 버킷리스트 발화를 실시간 전사한 뒤, 녹음 결과와 버킷리스트를 서로 연결된 기록으로 저장할 수 있다.

## 구현 전략 — 핵심 로직 먼저

UI보다 녹음 파이프라인과 데이터 무결성을 먼저 완성한다. 핵심 로직 단계에서는 SwiftUI 화면 없이 단위 테스트와 테스트용 호출 코드만으로 아래 흐름을 검증한다.

```text
사용자가 시작 버튼 선택
  → 첫 대본 문장 녹음 즉시 시작
  → 문장 전환마다 녹음 세그먼트 보관
  → 버킷리스트 세그먼트 + STT
  → 일시 정지·재개
  → 사용자가 종료 버튼 선택
  → 오디오 확정·평균 음량·발화 속도 계산
  → STT 결과를 편집 가능한 버킷리스트 초안으로 변환
  → 사용자 수정·확정
  → 오디오 파일 저장
  → TaedamRecord + TaedamRecordingSegment + BucketListItem 저장
  → recordID + bucketListID 반환
```

핵심 로직은 SwiftUI를 import하지 않으며 프로토콜을 통해 오디오, Speech, 파일 시스템, SwiftData에 접근한다. UI는 확정된 세션 상태와 서비스 결과를 표시하고 사용자 입력을 전달하는 역할만 담당한다.

### 핵심 로직 완료 게이트

아래 조건을 모두 통과하기 전에는 본 UI 구현을 시작하지 않는다.

- 시작 버튼 이벤트 전에는 녹음 파일이 생성되지 않고, 시작 이벤트 후 첫 문장의 녹음 파일을 만들 수 있다.
- 일시 정지·재개 후에도 유효 녹음 시간과 오디오 순서가 정확하다.
- 부분 STT 결과를 중복 없이 합쳐 하나의 확정 버킷리스트 문장으로 만들 수 있다.
- 확정 STT 결과를 편집 가능한 초안으로 만들고, 수정된 최종 텍스트를 검증할 수 있다.
- 각 JSON 문장 인덱스와 해당 문장을 읽은 녹음 파일이 정확히 연결된다.
- 버킷리스트 발화는 별도 세그먼트로 보관된다.
- 사용자가 종료 이벤트를 보내기 전에는 녹음이 임의로 끝나지 않는다.
- 평균 음량과 발화 속도 계산이 단위 테스트를 통과한다.
- `TaedamRecord`, 문장별 `TaedamRecordingSegment`, `BucketListItem`을 함께 저장하고 앱 재실행 뒤 다시 조회할 수 있다.
- 실패 시 불완전한 SwiftData 레코드와 고아 오디오 파일이 남지 않는다.
- UI 없이 세션 시작부터 `recordID`, `bucketListID` 반환까지 통합 테스트가 통과한다.

## 사용자 흐름

1. 태담 화면이 대본과 태담 정보를 전달받는다.
2. 필요한 마이크·음성 인식 권한이 준비됐는지 확인한다.
3. 화면은 `ready` 상태로 대기하며 사용자가 시작 버튼을 누르기 전에는 녹음하지 않는다.
4. 사용자가 시작 버튼을 누르면 카운트다운 없이 첫 번째 대본 문장의 녹음을 즉시 시작한다.
5. 대본 구간에서는 현재 읽을 줄을 강조하고 앞뒤 문장을 함께 보여준다.
6. 현재 줄이 바뀌면 이전 문장의 녹음 세그먼트를 닫고 다음 문장의 세그먼트를 시작한 뒤 Apple Music 가사처럼 목록을 내려준다.
7. 준비된 대본이 끝나면 마지막 문장 세그먼트를 닫고 버킷리스트 녹음·STT 세그먼트를 시작한다.
8. 버킷리스트 발화 구간에서는 사용자의 말을 실시간으로 전사해 화면에 이어서 보여준다.
9. 사용자는 하단 컨트롤러에서 녹음을 일시 정지하거나 재개할 수 있다.
10. 사용자가 종료 버튼을 누르면 전체 태담 녹음과 STT를 종료한다.
11. 분석 로딩 화면에서 오디오를 확정하고 평균 음량과 발화 속도를 계산한다.
12. 결과 화면에서 확정된 전사문을 편집 가능한 버킷리스트 텍스트로 보여준다.
13. 사용자는 오인식된 내용이나 문장을 직접 수정하고 완료 버튼을 누른다.
14. 문장별 녹음 파일, 분석 메타데이터와 사용자가 확정한 버킷리스트를 함께 저장한다.
15. 서로 연결된 태담 기록 ID와 버킷리스트 ID를 결과 화면에 전달한다.

## 화면 상태

```text
ready
  └─ recordingScript
       └─ recordingBucketList
            └─ finalizingTranscription
                 └─ processing
                      └─ editingBucketList
                           └─ saving
                                └─ completed

recordingScript / recordingBucketList
  ├─ paused ── 재개 ── 이전 녹음 상태
  ├─ finishing ── finalizingTranscription
  └─ failed
```

- `ready` 상태에서는 시작 버튼을 보여주며 자동으로 녹음을 시작하지 않는다.
- 녹음 중에는 현재 대본 또는 버킷리스트 전사문과 하단 녹음 컨트롤러를 표시한다.
- 일시 정지 중에는 전사와 음량 측정을 멈추되 이전 결과는 유지한다.
- 전사 확정 후에는 분석 로딩 화면을 표시한다.
- 분석이 끝나면 결과 화면에서 STT 결과를 편집 가능한 텍스트로 보여주고 사용자의 완료 입력을 기다린다.
- 처리·저장 중에는 중복 입력을 막고 완료 전 화면 이탈을 제어한다.
- 실패 시 사용자가 다시 시도하거나 안전하게 이전 화면으로 돌아갈 수 있어야 한다.

## 제품 백로그

### TAEDAM-01. 태담 세션 상태와 연결 계약 정의

**우선순위**: P0

**작업**

- 화면 상태를 표현하는 `TaedamSessionState`를 정의한다.
- 홈 또는 대본 선택 화면에서 받을 입력 모델을 정의한다.
- 결과 화면으로 전달할 출력 모델을 정의한다.
- 화면 상태와 오디오 서비스 상태가 서로 다른 값으로 어긋나지 않도록 단일 상태 소스를 둔다.

**입력 계약 초안**

```swift
struct TaedamSessionInput: Sendable {
    let scriptID: String
    let scriptVersion: Int
    let gestationalWeek: Int
    let title: String
    let lines: [ScriptLineDTO]
    let bucketListPrompt: String
}
```

**출력 계약 초안**

```swift
struct TaedamSessionResult: Sendable {
    let recordID: UUID
    let bucketListID: UUID
}
```

**완료 조건**

- 시작 대기부터 저장 완료까지 모든 상태 전환이 열거형으로 표현된다.
- 일시 정지 후 재개할 때 대본 구간과 버킷리스트 발화 구간 중 올바른 상태로 돌아간다.
- 다른 Feature는 오디오 구현을 알지 않고 입력과 결과만 주고받는다.

### TAEDAM-02. 사용자 녹음 시작

**우선순위**: P0
**선행 작업**: TAEDAM-01

**작업**

- `ready` 상태에서 사용자가 누를 수 있는 녹음 시작 버튼을 제공한다.
- 시작 버튼 이벤트가 들어오기 전에는 녹음을 시작하지 않는다.
- 시작 버튼을 누르면 중간 카운트다운이나 자동 전환 없이 녹음을 즉시 시작한다.
- 시작 버튼을 연속으로 눌러도 녹음 시작 요청을 한 번만 처리한다.
- 녹음 시작에 실패하면 `recordingScript`로 전환하지 않고 재시도 가능한 오류를 보여준다.

**완료 조건**

- 화면 진입만으로는 녹음 파일이 생성되지 않는다.
- 사용자가 시작 버튼을 누른 경우에만 녹음을 시작한다.
- 시작 버튼과 실제 녹음 시작 사이에 카운트다운 화면이 나타나지 않는다.
- 중복 입력에도 녹음 세션과 파일은 하나만 생성된다.

### TAEDAM-03. 오디오 녹음 기반 기능

**우선순위**: P0
**선행 작업**: TAEDAM-01

**작업**

- `AVAudioSession`의 녹음 카테고리와 활성화 정책을 설정한다.
- 시작 버튼 이후 첫 번째 대본 문장의 녹음 세그먼트를 시작한다.
- 대본 문장이 바뀔 때 현재 세그먼트를 닫고 다음 `sentenceIndex`의 세그먼트를 시작한다.
- 대본이 끝나면 버킷리스트 전용 녹음 세그먼트로 전환한다.
- 사용자는 하나의 태담 세션으로 인식하되 내부 파일은 문장별로 분리한다.
- 녹음 시작·일시 정지·재개·종료를 제공하는 서비스 프로토콜을 정의한다.
- 사용자의 종료 이벤트 전에는 대본 종료, 무음 또는 경과 시간만으로 녹음을 끝내지 않는다.
- 오디오 세션 인터럽트와 입력 장치 변경을 처리한다.
- 오디오 콜백에서 UI를 직접 변경하지 않고 상태 업데이트를 안전하게 전달한다.

**완료 조건**

- 사용자가 시작 버튼을 누른 후 첫 번째 문장의 오디오 파일이 생성된다.
- 모든 대본 문장의 `sentenceIndex`와 녹음 파일이 일대일로 연결된다.
- 버킷리스트 발화는 대본 문장과 구분된 세그먼트로 생성된다.
- 세그먼트 순서를 정렬하면 사용자가 말한 전체 순서가 유지된다.
- 일시 정지한 시간은 녹음 길이와 발화 속도 계산에서 제외된다.
- 재개 후 기존 녹음 내용을 잃지 않는다.
- 전화·Siri 등 시스템 인터럽트가 발생해도 손상된 기록을 저장하지 않는다.

### TAEDAM-04. 대본 가사형 진행 화면

**우선순위**: P0
**선행 작업**: TAEDAM-01, TAEDAM-03

**작업**

- 현재 문장을 포함해 약 4줄의 대본 문맥을 보여준다.
- 현재 읽을 문장은 선명하고 굵게, 나머지 문장은 흐리게 표현한다.
- 현재 줄이 바뀔 때 다음 문장이 자연스럽게 내려오도록 스크롤한다.
- 빠르게 연속해서 줄이 바뀌어도 애니메이션이 중첩되어 흔들리지 않게 한다.
- 마지막 준비 대본이 끝나면 버킷리스트 프롬프트와 발화 구간으로 전환한다.

**완료 조건**

- 현재 줄은 언제나 한 개만 강조된다.
- 줄 전환 후 강조 위치와 스크롤 위치가 일치한다.
- 긴 문장, 짧은 문장, 4줄 미만 대본에서도 레이아웃이 깨지지 않는다.
- 마지막 줄 이후 대본 인덱스 범위를 벗어나지 않는다.

> 대본의 다음 줄과 마지막 버킷리스트 프롬프트로 전환하는 기준은 아래 미결정 항목에서 확정해야 한다.

### TAEDAM-05A. 버킷리스트 발화 실시간 전사

**우선순위**: P0
**선행 작업**: TAEDAM-01, TAEDAM-03

**작업**

- 마지막 준비 대본 이후 버킷리스트 프롬프트를 표시한다.
- Apple `Speech` 프레임워크를 이용해 사용자의 버킷리스트 발화를 실시간으로 전사한다.
- 부분 인식 결과를 화면에 반영하고 확정 결과와 중복되지 않게 합친다.
- 전사 결과가 길어지면 최신 문장이 보이도록 자동 스크롤한다.
- 일시 정지 시 인식 요청을 멈추고 재개 시 새 요청을 안전하게 시작한다.
- 종료 시 최종 인식 결과를 기다린 뒤 앞뒤 공백을 제거한 버킷리스트 문장을 확정한다.
- 확정된 원본 전사문으로 편집 가능한 `BucketListDraft`를 만든다.
- 네트워크·인식 제한·무음 등으로 전사가 실패해도 원본 녹음은 계속 보존한다.

**완료 조건**

- 버킷리스트 발화 구간에서 말한 내용이 지연 후 화면에 표시된다.
- 부분 결과가 갱신될 때 같은 문장이 반복해서 붙지 않는다.
- 일시 정지 중에는 새로운 전사문이 추가되지 않는다.
- 전사가 끝나면 확정 결과가 읽기 전용 문장이 아니라 편집 가능한 초안으로 전달된다.
- 확정된 전사문과 원본 녹음의 버킷리스트 구간이 같은 세션에 속한다.
- 전사 실패가 이미 녹음된 오디오 유실로 이어지지 않는다.

### TAEDAM-05B. 버킷리스트 전사문 검토·수정

**우선순위**: P0
**선행 작업**: TAEDAM-05A

**초안 모델**

```swift
struct BucketListDraft: Equatable, Sendable {
    let rawTranscript: String
    var editedText: String
}
```

**작업**

- 최종 STT 결과를 `rawTranscript`와 `editedText`의 초기값으로 사용한다.
- `editedText`를 편집 가능한 텍스트 입력으로 보여준다.
- 사용자가 오인식, 띄어쓰기, 표현을 직접 고칠 수 있게 한다.
- 저장 확인 시 앞뒤 공백과 불필요한 빈 줄을 정리한다.
- 정리한 텍스트가 비어 있으면 저장을 막고 직접 입력할 수 있게 한다.
- STT가 실패하거나 빈 결과를 반환해도 빈 편집 화면에서 직접 버킷리스트를 작성할 수 있게 한다.
- 사용자가 저장을 확인한 뒤에만 `BucketListItem`을 생성한다.
- 원본 전사문은 발화 속도 분석에 사용하고, 사용자가 수정한 텍스트는 버킷리스트 저장에 사용한다.

**완료 조건**

- 전사가 끝나면 STT 결과가 편집 가능한 텍스트로 표시된다.
- 사용자가 수정한 문장이 화면을 다시 그려도 유지된다.
- 공백만 있는 문장으로는 저장을 완료할 수 없다.
- 저장된 `BucketListItem.content`는 원본 STT가 아니라 사용자가 최종 확인한 텍스트와 일치한다.
- 텍스트 수정이 원본 녹음 파일과 발화 속도 계산에 영향을 주지 않는다.

### TAEDAM-06. 음량 기반 배경 파동 애니메이션

**우선순위**: P1
**선행 작업**: TAEDAM-03

**작업**

- 녹음 중 오디오 레벨을 일정 주기로 샘플링한다.
- 원시 dBFS 값을 화면 애니메이션에 사용할 정규화 값으로 변환한다.
- 음량이 커질수록 파동의 높이 또는 진폭이 커지도록 한다.
- 급격한 값 변화가 화면 떨림으로 보이지 않도록 보간 또는 smoothing을 적용한다.
- 일시 정지 시 파동을 정지 상태로 전환한다.

**완료 조건**

- 무음에서는 파동이 최소 크기를 유지한다.
- 큰 소리에서 파동이 지정한 최대 범위를 넘어 레이아웃을 침범하지 않는다.
- 애니메이션이 메인 스레드의 녹음·전사 처리를 막지 않는다.
- 일시 정지와 재개 상태가 파동에 즉시 반영된다.

### TAEDAM-07. 하단 녹음 컨트롤러와 종료 처리

**우선순위**: P0
**선행 작업**: TAEDAM-03

**작업**

- 태담 제목·주차 정보와 일시 정지·재개 버튼을 표시한다.
- 버튼을 연속으로 눌러도 상태 전환을 한 번만 처리한다.
- 상단 종료 버튼을 누르면 녹음과 전사를 순서대로 종료한다.
- 저장 처리 중에는 컨트롤을 비활성화한다.

**완료 조건**

- 녹음 중 버튼은 일시 정지 동작과 아이콘을 제공한다.
- 일시 정지 중 버튼은 재개 동작과 아이콘을 제공한다.
- 종료 후 오디오 입력과 음성 인식 작업이 남아 있지 않는다.
- 종료 요청이 여러 번 들어와도 기록은 하나만 생성된다.

### TAEDAM-08. 녹음 종료와 분석값 계산

**우선순위**: P0
**선행 작업**: TAEDAM-03, TAEDAM-05A

**작업**

- 사용자의 종료 버튼 이벤트를 받으면 오디오 입력과 STT를 순서대로 종료한다.
- 현재 녹음 세그먼트를 닫고 모든 문장별 파일이 재생 가능한지 검증한다.
- 녹음 중 수집한 레벨로 평균 음량을 계산한다.
- 확정 전사문과 유효 발화 시간으로 발화 속도를 계산한다.
- 분석 또는 파일 확정 실패 시 재시도 가능한 오류로 전달한다.

**완료 조건**

- 대본 문장 세그먼트와 버킷리스트 세그먼트의 순서가 실제 발화 순서와 일치한다.
- 각 대본 문장 세그먼트가 올바른 JSON `sentenceIndex`를 참조한다.
- 일시 정지 구간이 무음으로 불필요하게 포함되지 않는다.
- 평균 음량과 발화 속도 결과에 `NaN`, 무한대 또는 음수 시간이 포함되지 않는다.
- 실패 시 임시 파일과 불완전한 SwiftData 레코드가 남지 않는다.

### TAEDAM-09. SwiftData 기록 저장

**우선순위**: P0
**선행 작업**: TAEDAM-05B, TAEDAM-08

**저장 모델 기준**

상세 필드와 관계의 권위 문서는 [`../design/taedam-data-contracts.md`](../design/taedam-data-contracts.md)다.

| 필드 | 타입 | 설명 |
|---|---|---|
| `id` | `UUID` | 기록 식별자 |
| `scriptID` | `String` | 사용한 대본 식별자 |
| `scriptVersion` | `Int` | 녹음 당시 대본 버전 |
| `babyNicknameSnapshot` | `String` | 녹음 당시 사용한 아기 태명 |
| `recordedAt` | `Date` | 녹음 완료 날짜 |

**문장별 녹음 세그먼트 모델 초안**

| 필드 | 타입 | 설명 |
|---|---|---|
| `id` | `UUID` | 세그먼트 식별자 |
| `taedamRecordID` | `UUID` | 부모 태담 기록 ID |
| `kind` | `String` | `scriptSentence` 또는 `bucketList` |
| `scriptSentenceIndex` | `Int?` | JSON 문장 배열 인덱스, 버킷리스트면 `nil` |
| `sequence` | `Int` | 세션 내 재생 순서 |
| `audioRelativePath` | `String` | 문장별 오디오 상대 경로 |
| `duration` | `TimeInterval` | 세그먼트 녹음 시간 |

**아기 태명 모델 초안**

| 필드 | 타입 | 설명 |
|---|---|---|
| `id` | `UUID` | 아기 프로필 식별자 |
| `nickname` | `String` | 현재 태명 |
| `createdAt` | `Date` | 최초 생성 날짜 |
| `updatedAt` | `Date` | 마지막 수정 날짜 |

**버킷리스트 저장 모델 초안**

| 필드 | 타입 | 설명 |
|---|---|---|
| `id` | `UUID` | 버킷리스트 식별자 |
| `taedamRecordID` | `UUID` | 버킷리스트를 만든 태담 기록 식별자 |
| `content` | `String` | 사용자가 수정하고 최종 확인한 버킷리스트 문장 |
| `createdAt` | `Date` | 버킷리스트 생성 날짜 |

**저장 원칙**

- 큰 오디오 데이터를 SwiftData 속성에 직접 넣지 않는다.
- 정적 대본 원본은 번들 JSON에 두고 SwiftData에 중복 저장하지 않는다.
- 현재 태명은 `BabyProfile`에 저장하고, 과거 맥락 보존을 위해 녹음 당시 태명을 `TaedamRecord`에 스냅샷으로 저장한다.
- 문장별 녹음 파일은 Application Support의 기록별 하위 폴더에 저장한다.
- SwiftData에는 JSON 문장 인덱스, 오디오 상대 경로와 녹음 길이를 저장한다.
- 태담 기록과 버킷리스트 항목은 식별자 또는 SwiftData 관계로 연결한다.
- 사용자가 최종 확인한 버킷리스트 문장은 `BucketListItem.content`만 원본으로 사용하고 태담 기록에 중복 저장하지 않는다.
- 개별 dB 샘플, 평균 음량과 발화 속도는 현재 SwiftData 저장 범위에 포함하지 않는다.
- 현재 범위에서는 사용자가 확인한 전체 텍스트를 여러 항목으로 분리하지 않고 하나의 `content`로 저장한다.
- 태담 기록, 문장별 녹음 세그먼트와 버킷리스트 항목은 하나의 저장 작업에서 함께 생성한다.
- 레코드 저장 실패 시 새로 만든 오디오 파일을 정리한다.
- 오디오 파일 삭제와 SwiftData 레코드 삭제는 하나의 Store API에서 처리한다.

**완료 조건**

- 앱을 종료하고 다시 실행해도 저장된 기록과 오디오를 찾을 수 있다.
- 같은 녹음을 종료 버튼 중복 입력으로 두 번 저장하지 않는다.
- 같은 세션에서 버킷리스트 항목이 두 번 생성되지 않는다.
- 빈 문자열 또는 공백만 있는 버킷리스트를 저장하지 않는다.
- 파일이 유실된 기록을 읽을 때 앱이 크래시하지 않고 복구 가능한 상태를 반환한다.
- 저장 성공 후 생성된 `recordID`와 `bucketListID`를 결과 화면에 전달한다.

### TAEDAM-10. 다른 Feature와 통합

**우선순위**: P0
**선행 작업**: TAEDAM-01, TAEDAM-09

**작업**

- 홈 또는 대본 상세 구현체에서 `TaedamSessionInput`을 전달받는다.
- 완료 후 `recordID`와 `bucketListID`를 간단 결과 또는 리포트 화면에 전달한다.
- 다른 개발자가 구현한 화면이 내부 오디오 서비스와 SwiftData 모델을 직접 조작하지 않게 한다.
- 임시 mock 데이터와 실제 연결 코드를 분리한다.

**완료 조건**

- 호출 화면은 입력 모델만 만들어 태담 흐름을 시작할 수 있다.
- 결과 화면은 `recordID`로 태담 기록을, `bucketListID`로 생성된 버킷리스트를 조회할 수 있다.
- 대본 모델이 변경되더라도 태담 Feature의 입력 변환 지점 한 곳만 수정하면 된다.

### TAEDAM-11. 테스트와 실패 복구

**우선순위**: P1
**선행 작업**: TAEDAM-01~10

**테스트 범위**

- 시작 버튼 이벤트 전에는 녹음이 시작되지 않는지 검증하는 테스트
- 시작 버튼 이벤트가 들어오면 카운트다운 없이 녹음 상태로 전환하는 테스트
- 사용자 종료 이벤트 전에는 녹음이 유지되는지 검증하는 테스트
- 대본 인덱스 이동과 마지막 줄 처리 단위 테스트
- 버킷리스트 부분 전사·확정 전사 병합 단위 테스트
- 전사문 초깃값과 사용자 수정값 분리 테스트
- 수정 텍스트 공백 정리 및 빈 값 검증 테스트
- 사용자 수정값이 `BucketListItem.content`에 저장되는 통합 테스트
- 빈 전사 결과의 버킷리스트 저장 방지 테스트
- 일시 정지 시간을 제외한 녹음 시간 계산 테스트
- 평균 음량과 발화 속도 계산 테스트
- 문장별 녹음 파일 확정 성공·실패 테스트
- JSON 문장 인덱스와 녹음 세그먼트 매핑 테스트
- 세그먼트 순서 및 누락 검증 테스트
- 사용자 종료 전 녹음이 유지되는지 검증하는 테스트
- SwiftData 저장·조회·삭제 통합 테스트
- 종료 버튼 중복 입력 방지 테스트
- 권한 거부·오디오 인터럽트·전사 실패 복구 테스트

**완료 조건**

- 오디오와 Speech 프레임워크는 프로토콜 뒤에 두어 테스트 대역으로 교체할 수 있다.
- 시간 흐름은 실제로 기다리지 않고 제어 가능한 Clock을 통해 테스트한다.
- 주요 상태 전환과 저장 실패 경로가 자동 테스트로 검증된다.

## 구현 경계와 서비스 역할

```text
Taedam Feature
├── TaedamSessionView
├── TaedamSessionViewModel
├── TaedamSessionState
└── BucketListDraft             # 원본 STT와 편집 중 텍스트

Core/Services/Audio
├── AudioRecordingService       # 녹음·일시 정지·재개·레벨 측정
└── SpeechTranscribingService   # 실시간 전사

Core/Services/Analysis
└── TaedamAnalysisService       # 평균 음량·발화 속도 계산

Persistence
├── TaedamRecord                # SwiftData 모델

```

## 미결정 항목

아래 항목은 구현 전에 기획·디자인·연결 담당자와 확정해야 한다.

1. **대본 줄 전환 기준**: 음성 인식으로 현재 줄을 읽었다고 판단할지, 정해진 시간마다 넘길지, 사용자가 직접 넘길지.
2. **버킷리스트 전환 기준**: 마지막 준비 대본 인식 완료 즉시 프롬프트를 보여줄지, 별도 안내 또는 버튼을 둘지.
3. **여러 항목 처리**: 한 발화에서 여러 버킷리스트를 말했을 때 하나의 문장으로 저장할지, 여러 항목으로 분리할지. 현재 초안은 하나의 항목으로 저장한다.
4. **수정 화면 이탈 정책**: 수정 중 뒤로 갈 때 초안을 유지할지, 녹음 결과와 함께 폐기할지.
5. **발화 속도 단위**: 한국어 어절/분, 글자/분, 음절/분 중 어떤 지표를 리포트에서 사용할지.
6. **평균 데시벨 정의**: dBFS 평균, 정규화된 음량 점수 등 리포트가 요구하는 계산식.
7. **오디오 형식**: `m4a(AAC)` 또는 `caf(PCM)` 등 최종 저장 형식과 품질.
8. **저장 제한**: 최대 녹음 길이, 파일 보관 기간 및 앱 저장 공간 부족 시 정책.
9. **권한 화면 책임**: 진입 전에 다른 화면에서 권한을 확보할지, 태담 Feature가 직접 권한 요청 UI를 제공할지.
10. **화면 이탈 정책**: 녹음 중 뒤로 가기 또는 종료하기를 눌렀을 때 확인 팝업과 임시 녹음 보존 여부.
11. **문장 재녹음 정책**: 이전 문장으로 돌아가 다시 읽을 때 기존 파일을 교체할지 여러 take를 보관할지.
12. **합본 파일 필요 여부**: 문장별 파일 외에 전체 태담 연속 재생용 합본 파일을 추가 생성할지.

## 완료 정의

- P0 백로그의 완료 조건을 모두 충족한다.
- SwiftLint error 없이 빌드된다.
- 실제 기기에서 마이크 녹음, Speech 전사, 일시 정지·재개를 검증한다.
- 전사 완료 후 사용자가 버킷리스트 문장을 수정하고 확정할 수 있다.
- 녹음 완료 후 앱 재실행 뒤에도 기록, 오디오 및 연결된 버킷리스트를 열 수 있다.
- 홈 진입점, 결과 화면 및 버킷리스트 구현체와 입력·출력 계약으로 연결된다.
- 접근 권한 거부, 시스템 인터럽트, 저장 실패 상황에서 앱이 크래시하지 않는다.
